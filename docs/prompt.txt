## Noise model required for each algorithm

### 1. FRQI mode

Use a noise model representing **rotation and controlled-gate errors**.

Reason:

FRQI encodes DNA or image information using parameterized rotation gates, especially controlled `RY` rotations. Small gate inaccuracies modify the encoded amplitudes.

Preferred implementation:

* Add a small coherent over-rotation or depolarizing error to `ry`, `u`, `cx` or the actual basis gates produced after transpilation.
* Ensure the noise is attached to gates that actually exist in the transpiled FRQI circuit.
* Use a realistic but visible error rate.
* Avoid using an error rate so large that the output becomes completely random.

Suggested starting values:

```python
single_qubit_error = 0.002
two_qubit_error = 0.01
```

Preferred mitigation:

* Transpile with `optimization_level=3`.
* Compare the optimized noisy result against the ideal result.
* Report original and transpiled circuit depth and `CX` count.

### 2. Grover/QGSA mode

Use **two-qubit depolarizing noise**.

Reason:

The Grover oracle and diffuser contain many controlled and multi-controlled operations. After decomposition, these become multiple `CX` gates, so two-qubit gate noise is the most relevant.

Suggested starting values:

```python
single_qubit_error = 0.001
two_qubit_error = 0.015
```

Apply the strongest noise to `cx` or the transpiled two-qubit basis gate.

Preferred mitigation:

Implement a lightweight form of **zero-noise extrapolation** for the main success metric.

Run the noisy circuit using at least these effective noise scale factors:

```text
1x, 2x, 3x
```

For each factor:

* Scale the depolarizing error probabilities safely.
* Run the same circuit with the same number of shots.
* Extract the probability of the expected target index or total valid target states.

Estimate the zero-noise probability using a simple linear or quadratic fit.

Return:

* Ideal target probability
* Raw noisy target probability at 1x
* Mitigated or extrapolated target probability
* False-positive probability
* Noise scale results

Do not apply ZNE separately to every output state unless the current architecture already supports it. Apply it mainly to the selected success metric.

### 3. YLC mode

Use **measurement/readout noise**.

Reason:

The YLC result is determined from measured output bitstrings, so incorrect `0 → 1` and `1 → 0` measurements directly affect the final result.

Suggested starting readout matrix:

```python
ReadoutError([
    [0.97, 0.03],
    [0.04, 0.96]
])
```

Preferred mitigation:

Implement readout-error mitigation.

A simple acceptable approach is:

* Build the single-qubit assignment matrix.
* Extend it for the measured register using tensor products or independent local correction.
* Correct the noisy output probability vector.
* Clip negative corrected probabilities to zero.
* Renormalize the corrected distribution.

Return:

* Ideal distribution
* Raw noisy distribution
* Mitigated distribution
* Correct-answer probability before and after mitigation

Use Qiskit Experiments readout mitigation only when it is already installed and compatible. Otherwise implement a small local assignment-matrix correction without introducing a heavy dependency.
